# Миграция файлов 1С:ДО → Nextcloud

Набор инструментов для переноса документов из **1С:Документооборот** (ДО 2.x / 3.x) в **Nextcloud** с сохранением:

- иерархии папок
- всех версий файлов
- метаданных (автор, даты, описание, комментарии к версиям)
- пометок на удаление

---

## Структура репозитория

```
1c/
  export_do_files.bsl         — Внешняя обработка 1С: выгрузка файлов на диск
python/
  upload_to_nextcloud.py      — Python-скрипт: загрузка в Nextcloud
  requirements.txt
```

---

## Шаг 1 — Выгрузка из 1С:ДО

### Что делает обработка

- Обходит все файлы справочника `ФайлыДокументов` (или `Файлы` в ДО 3.x).
- Для каждого файла выгружает **все версии** из регистра `ВерсииФайлов`.
- Рядом с каждым файлом/версией создаёт `<имя>.meta.json` с метаданными.
- Сохраняет сводный `_export_index.json` и лог `_export_log_*.txt`.

### Структура каталога на диске

```
C:\Export_1CDO\
  _export_index.json
  _export_log_20240101_120000.txt
  Входящие\
    Договор_2023.docx
    Договор_2023.docx.meta.json
    _versions\
      Договор_2023.v001.docx
      Договор_2023.v001.docx.meta.json
      Договор_2023.v002.docx
      Договор_2023.v002.docx.meta.json
  Исходящие\
    ...
```

### Пример `.meta.json`

```json
{
  "source_system": "1C:DO",
  "name": "Договор_2023",
  "extension": "docx",
  "description": "Договор с ООО Ромашка",
  "author": "Иванов Иван",
  "created_at": "2023-03-15T10:00:00",
  "modified_at": "2023-11-20T14:32:00",
  "folder": "Входящие",
  "guid_1c": "a1b2c3d4-...",
  "is_deleted": false,
  "version": {
    "number": 2,
    "total": 2,
    "is_current": true,
    "size_bytes": 45312,
    "comment": "Финальная редакция",
    "version_author": "Петров Пётр",
    "version_date": "2023-11-20T14:32:00"
  }
}
```

### Подключение обработки

1. Откройте 1С:Предприятие с базой 1С:ДО.
2. `Файл → Открыть` → выберите `1c/export_do_files.bsl`  
   (или добавьте код в новую внешнюю обработку через конфигуратор).
3. В самом конце файла задайте параметры:

```bsl
КаталогВыгрузки   = "C:\Export_1CDO\";  // путь для выгрузки
ВыгружатьВерсии   = Истина;              // все версии
ВыгружатьУдалённые = Ложь;              // пропускать удалённые
```

4. Запустите процедуру `ВыполнитьВыгрузку()`.

> **Требования к правам:** роль *Полные права* или права на чтение справочников  
> `ФайлыДокументов`, `ПапкиФайлов` и регистра `ВерсииФайлов`.

## Шаг 2 — Загрузка в Nextcloud

### Установка зависимостей

```bash
cd python
pip install -r requirements.txt
```

### Базовый запуск

```bash
python upload_to_nextcloud.py \
    --export-dir /path/to/Export_1CDO \
    --nextcloud-url https://cloud.example.com \
    --username admin \
    --password "ваш_пароль" \
    --remote-dir /1CDO_Migration
```

### Все параметры

| Параметр | По умолчанию | Описание |
|---|---|---|
| `--export-dir` | — | Путь к каталогу выгрузки (обязательно) |
| `--nextcloud-url` | — | URL Nextcloud (обязательно) |
| `--username` | — | Логин (обязательно) |
| `--password` | — | Пароль или app-token (обязательно) |
| `--remote-dir` | `/1CDO_Migration` | Целевая папка в Nextcloud |
| `--no-versions` | выкл | Не загружать старые версии |
| `--no-tags` | выкл | Не назначать теги |
| `--no-comments` | выкл | Не добавлять комментарии к файлам |
| `--no-sidecar` | выкл | Не загружать `.meta.json` рядом с файлом |
| `--threads` | `2` | Число параллельных потоков загрузки |
| `--state-file` | `upload_state.json` | Файл для возобновления прерванной загрузки |
| `--log-file` | `upload.log` | Файл журнала |

### Возобновление прерванной загрузки

Скрипт сохраняет состояние в `upload_state.json`. При повторном запуске с теми же параметрами уже загруженные файлы пропускаются автоматически.

### Что создаётся в Nextcloud

- Зеркальная иерархия папок из 1С:ДО.
- Текущая версия файла в соответствующей папке.
- Старые версии в подпапке `_versions/`.
- `<имя>.meta.json` рядом с каждым файлом.
- **Теги** на файле: `author:Иванов`, `1cdo:Входящие`, `versions:3`.
- **Комментарий** к файлу с исходными метаданными из 1С:ДО.

---

## Рекомендуемый порядок миграции (Nextcloud)

1. Сделайте тестовую выгрузку одной папки (ограничьте запрос в обработке условием `И ф.Родитель = &ТестоваяПапка`).
2. Запустите скрипт с `--no-tags --no-comments` для проверки структуры.
3. Убедитесь, что файлы открываются из Nextcloud.
4. Запустите полную миграцию.
5. После проверки удалите `.meta.json` сайдкары если они не нужны.

## Шаг 2 (альтернатива) — Загрузка в S3-совместимое хранилище (MinIO / Ceph)

Скрипт `python/s3_upload.py` загружает результат выгрузки в любое S3-совместимое
хранилище с поддержкой версионирования и дедупликации на уровне объектов.

### Возможности S3-загрузчика

| Функция | Описание |
|---|---|
| **Multipart upload** | Автоматически для файлов ≥ порога (по умолчанию 100 МиБ). Размер части рассчитывается динамически — не более 9 999 частей (поддержка файлов до 2.5 ТБ и выше) |
| **Resumable multipart** | `UploadId` и список загруженных частей сохраняются в state-файле. При перезапуске продолжает с прерванной части |
| **Версионирование** | Все исторические версии загружаются в **один S3-ключ** в хронологическом порядке. Нативное S3-версионирование хранит отдельную запись для каждого PUT |
| **Метаданные версии** | Автор, дата, комментарий версии передаются как S3 user metadata (`x-amz-meta-*`) на каждой версии |
| **Объектная дедупликация** | SHA-256 вычисляется перед загрузкой. Если идентичное содержимое уже есть в другом ключе — вместо повторного хранения загружается ссылочный объект (~0.5 КБ). Индекс SHA→ключ хранится локально + синхронизируется в S3 (`_dedup/index.json.gz`) |
| **Параллельность** | `--threads` параллельных файлов, `--part-threads` параллельных частей внутри одного multipart |
| **Возобновление** | State-файл содержит список завершённых файлов/версий. Повторный запуск пропускает уже загруженное |

### Установка зависимостей

```bash
cd python
pip install -r requirements.txt
```

### Запуск (MinIO)

```bash
python s3_upload.py \
    --export-dir /mnt/Export_1CDO \
    --endpoint-url http://minio.company.ru:9000 \
    --access-key ACCESS_KEY \
    --secret-key SECRET_KEY \
    --bucket 1cdo-archive \
    --prefix 1CDO/ \
    --threads 4 \
    --part-threads 8
```

### Запуск (Ceph RadosGW)

```bash
python s3_upload.py \
    --export-dir /mnt/Export_1CDO \
    --endpoint-url https://radosgw.company.ru \
    --access-key ACCESS_KEY \
    --secret-key SECRET_KEY \
    --bucket 1cdo-archive \
    --region default \
    --threads 4 \
    --part-threads 8
```

### Параметры S3-загрузчика

| Параметр | По умолчанию | Описание |
|---|---|---|
| `--export-dir` | — | Каталог выгрузки 1С:ДО (обязательно) |
| `--endpoint-url` | — | URL хранилища (обязательно) |
| `--access-key` | — | Access Key (обязательно) |
| `--secret-key` | — | Secret Key (обязательно) |
| `--bucket` | — | Имя S3-бакета (обязательно) |
| `--prefix` | `1CDO/` | Префикс для всех ключей в бакете |
| `--region` | `us-east-1` | Регион (для Ceph: `default`) |
| `--no-ssl-verify` | выкл | Отключить проверку TLS-сертификата |
| `--threads` | `2` | Параллельных файлов |
| `--part-threads` | `4` | Параллельных частей в multipart |
| `--multipart-threshold` | `100` | Порог multipart в МиБ |
| `--no-versions` | выкл | Не загружать исторические версии |
| `--no-dedup` | выкл | Отключить дедупликацию |
| `--state-file` | `s3_upload_state.json` | Файл состояния |
| `--dedup-index-file` | `dedup_index.json.gz` | Локальный файл dedup-индекса |
| `--log-file` | `s3_upload.log` | Файл журнала |

### Структура объектов в S3 после миграции

```
1cdo-archive/
  _dedup/
    index.json.gz               ← индекс SHA-256 → canonical_key (служебный)
  1CDO/
    Входящие/
      Договор.docx              ← текущая версия (последний PUT)
      Договор.docx.meta.json    ← метаданные текущей версии
                                   (S3 versioning хранит историю как отдельные версии
                                    одного ключа — S3 version IDs)
    Исходящие/
      Отчёт.xlsx                ← текущая версия
      Отчёт.xlsx                ← (версия V2, хранится в S3 versioning)
      Отчёт.xlsx                ← (версия V1, хранится в S3 versioning)
```

Каждая версия несёт S3 user metadata:
```
x-amz-meta-original-name:  Отчёт
x-amz-meta-author:         Иванов Иван
x-amz-meta-created-at:     2023-01-15T09:00:00
x-amz-meta-sha256:         a3f1c8...
x-amz-meta-ver-number:     2
x-amz-meta-ver-total:      3
x-amz-meta-ver-author:     Петров Пётр
x-amz-meta-ver-date:       2023-06-20T14:30:00
x-amz-meta-ver-comment:    Исправлены данные за Q2
```

### Ссылочный объект дедупликации

Если файл `B.docx` совпадает по содержимому с уже загруженным `A.docx`,
в S3 по ключу `B.docx` сохраняется ссылочный объект:

```json
{
  "__dedup_ref__": true,
  "sha256": "a3f1c8...",
  "canonical_key": "1CDO/Входящие/A.docx",
  "size_bytes": 45312
}
```

Для получения содержимого нужно обратиться к `canonical_key`.
Признак ссылочного объекта: `x-amz-meta-is-dedup-ref: true`.

### Подбор параметров параллельности

| Характеристика | Рекомендация |
|---|---|
| Много мелких файлов (< 100 МБ) | `--threads 8 --part-threads 2` |
| Крупные файлы (> 1 ГБ) | `--threads 2 --part-threads 8` |
| Смешанная нагрузка | `--threads 4 --part-threads 4` |
| Ширина канала 1 Гбит/с | `--threads 4 --part-threads 8` |
